故事地图解决“平铺 Backlog 看不见用户旅程”：把功能放回上下文，用横向叙事+纵向优先级切片，保证每个版本交付完整闭环体验。

## 结构

- **骨架（Backbone）**：用户活动（大步骤，按时间顺序排列）
- **任务层**：完成活动的具体操作
- **子任务/细节层**：边缘情况、优化项
- **发布线（Release Line）**：线以上是本次版本范围；下方为后续迭代

## 使用步骤（工作坊）

1) 从 {scenario} 讲一遍真实用户故事（不要从功能清单出发）
2) 贴出骨架活动（用户语言）
3) 在每个活动下补任务与子任务
4) 纵向排序：上方更核心、下方更低优先级
5) 画 Release 1（MVP）切片：必须能完成“一件有意义的事”
6) 为每条发布线写清楚要验证的假设与成功指标
7) 随洞察与迭代持续更新地图（活文档）
