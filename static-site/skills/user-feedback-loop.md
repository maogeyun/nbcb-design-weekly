闭环的核心不是“全做”，而是 **可预期的响应**：用户知道声音被记录、被评估、有结果。

## 五步执行

1) **多渠道收集**：应用内、邮件、社群、支持工单、商店评论等 {channels}，统一进入同一工单/数据库
2) **分类与严重度**：Bug / 体验 / 功能请求 / 账号与计费等；标影响面与紧急度
3) **关联路线图**：每条反馈链到主题或 Epic；重复反馈自动聚类升优先级
4) **优先处理高痛高频**：用同理心路线图或 RICE 与工程容量对齐
5) **回告用户**：已计划 / 已发布 / 暂不做的原因（模板化亦可）；发布说明中点名感谢典型反馈（可选）

## 指标

- 首次响应时间、解决时间、重复投诉率
- 「反馈→上线」的中位周期（用于内部改进，不必对外承诺）

## 常见坑

- 只收集不闭环，导致用户觉得“说了没用”
- 公开承诺具体日期却无法兑现——宁可给季度级预期
