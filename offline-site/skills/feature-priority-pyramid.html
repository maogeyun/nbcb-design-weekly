技能库 / feature priority pyramid

方案设计

feature priority pyramid

用特性优先级金字塔（功能性→可靠性→易用性→体验优化→差异化创新）校准资源投入顺序，避免跳层建设导致基础不稳。

金字塔的核心：先把地基打牢再装修。没有可靠性与可用性支撑的“惊喜功能”，会被一次崩溃或数据丢失彻底抵消。

五层结构（自下而上）

  • L1 功能性基础：核心任务能完成（能用）
  • L2 可靠性：稳定、不丢数据、性能可接受、异常有降级（可被信任）
  • L3 易用性：低认知负担、路径顺、错误提示清晰（无摩擦）
  • L4 体验优化：美感、动效、情感化、个性化（愉悦）
  • L5 差异化创新：独特价值与竞争壁垒（竞争优势）

落地做法（层级健康检查）

1) 为每层定义“及格线”（量化指标更好）

2) 审计现状：给每层标红/黄/绿

3) 将 {backlog} 按层级归类

4) 设资源规则：只要 L1/L2 有红/黄，本迭代至少 50% 投入基础层

5) 季度复盘更新阈值（产品成长会抬高用户期望）

常见误用

  • 用“上线压力”跳过 L2
  • 把“设计感”错当成与可靠性同级的基础
  • 认为 L1 做完就不必回头（缺少回归会退化）
