方案设计

需求到设计

把模糊需求一路收敛成可落地、可验证的设计方案，走通「需求 → 设计目标 → 设计策略 → 设计方案」四跳，并将分析结果导出为 MD 或 PDF 交付文件。当用户给出一段需求/诉求/问题，要求做需求分析、定设计目标、出设计策略、产出交互或视觉方案、写设计说明、或导出设计方案文档时使用。也适用于评审现有方案是否「目标-策略-方案」自洽。

需求到设计方案（四跳体系）

这是一套「不靠感觉拍脑袋」的设计推导能力，把模糊诉求逐层收敛：

  • 需求 → 要解决什么真实问题
  • 设计目标 → 做到什么程度算赢（可衡量）
  • 设计策略 → 用哪几类手段赢
  • 设计方案 → 具体长什么样、怎么跑

核心原则：每一跳都不能跳层，下一层必须能追溯回上一层；最终方案必须能回答「它如何兑现最初的可衡量指标」。

工作流程

收到需求后，按顺序走完四跳。每跳产出后立即用对应自检清单卡控，未通过不要进入下一跳。

任务进度：
- [ ] 跳 1：需求 → 设计目标（写出可衡量目标，过自检）
- [ ] 跳 2：设计目标 → 设计策略（每个目标有策略支撑，过自检）
- [ ] 跳 3：设计策略 → 设计方案（分层落地，覆盖 4 种状态，过自检）
- [ ] 收尾：用「完整案例」格式串起来，确认方案可回溯目标
- [ ] 交付：将结果导出为 MD 或 PDF 文件（见「交付产出」）

信息不足时，优先就「为谁 / 什么场景 / 现状痛点 / 成功长什么样」向用户追问，而不是直接臆造目标。

---

跳 1：需求 → 设计目标

别把「功能」当「目标」。 设计目标 = 用户收益 + 业务收益 + 可衡量标准。

  • ❌ 「设计一个智能客服入口」（这是功能）
  • ✅ 「降低人工客服成本 20%，同时让 80% 常见问题在 3 步内解决」

实用公式

> 面向 [某类用户]，在 [某场景] 下，通过 [设计干预]，实现 [可衡量的结果]。

示例：面向新用户，在首次下单场景中，通过简化填写流程 + 智能填充，实现转化率提升 15%。

推导方法（按需选用）

  • 双钻 Discover→Define：先发散收集问题（访谈/数据/竞品），再收敛成 1–3 个最关键目标。
  • OKR 式写法：一个目标 O 配 1–2 个可量化 KR。

| 目标 O | 关键结果 KR |

| --- | --- |

| 降低新用户上手门槛 | KR1 首屏任务完成率 ≥ 70%；KR2 平均完成时间 ≤ 90s |

| 提高关键操作效率 | KR1 高频操作步数 ≤ 3 步；KR2 误操作率下降 30% |

  • 用户目标 × 业务目标对齐表：确保两侧都被满足，再推出设计目标。

| 用户目标 | 业务目标 | 设计目标 |

| --- | --- | --- |

| 快速找到商品 | 提升 GMV | 搜索结果相关性 ≥ 90% |

| 少填信息 | 提高注册转化 | 注册字段减少 40% |

自检清单（跳 1）

  • [ ] 目标是否同时覆盖用户价值和业务价值？
  • [ ] 是否有明确的可衡量指标（数据或可用性测试可验证）？
  • [ ] 是否排除了「伪目标」（如「更好用」「看起来更高级」）？

---

跳 2：设计目标 → 设计策略

策略不是「风格」，而是「打法」：用什么样的结构、路径、规则来实现目标。

示例（目标：降低下单流失率）→ 策略：① 减少决策干扰（精简信息层级）② 缩短操作路径（合并步骤）③ 增强安全感（信任背书、退款保障展示）。

三类必选策略（通用框架）

  • A. 信息架构策略：导航扁平 vs 层级？页面按任务流/对象/角色分组？关键入口放首屏/Tab/悬浮？
  • B. 交互策略：操作路径（步数、跳转、返回）；反馈（加载/成功/失败/空态）；容错（撤销、二次确认、自动保存）。
  • C. 视觉与认知策略：优先级（F 型/Z 型布局）；强调方式（颜色、字号、留白、动效）；情感化（插画、文案语气、微文案）。

策略选择工具（快速版）

| 设计目标 | 推荐策略方向 |

| --- | --- |

| 提升效率 | 默认值 / 批量操作 / 快捷键 / 自动化 |

| 降低焦虑 | 进度提示 / 预估时间 / 明确后果 |

| 促进探索 | 推荐算法 / 相关入口 / 游戏化 |

| 提高转化 | 减少步骤 / 强化主操作 / 信任背书 |

自检清单（跳 2）

  • [ ] 每个目标是否都有对应策略支撑？
  • [ ] 策略之间是否冲突（如「强引导主操作」与「给足探索自由」需有优先级取舍）？
  • [ ] 是否考虑了非功能约束（性能、可达性、平台差异、合规）？这些往往是高风险场景的胜负手。

---

跳 3：设计策略 → 设计方案

从抽象到具体的落地逻辑

策略：减少操作步骤
 ↓
方案：将「地址填写页」合并进「下单页」
 ↓
细节：表单字段数量 / 校验规则 / 错误提示位置 / 键盘类型 / 一键回填逻辑

分层法（避免一上来就画 UI）

| 层级 | 关注点 | 工具 |

| --- | --- | --- |

| 任务层 | 用户要完成的任务流 | 流程图 / 泳道图 |

| 结构层 | 页面结构、布局 | 低保真线框图 |

| 表现层 | 颜色、字体、间距、图标 | 高保真 UI |

| 规则层 | 状态、异常、边界 | 设计说明 / 交互说明 |

方案必须覆盖的 4 种状态

  • ✅ 正常态：理想路径
  • ⚠️ 异常态：网络错误、失败、超时
  • 🕳 空态：无数据、未授权
  • ♻ 循环态：重复操作、撤销、回退

自检清单（跳 3）

  • [ ] 所有关键场景是否都被覆盖？
  • [ ] 异常态、空态、边界态、权限态是否补齐？
  • [ ] 开发/测试能否根据方案直接实现？
  • [ ] 方案能否说清如何兑现跳 1 的可衡量指标？

---

输出格式：用「完整案例」串起来

最终交付按以下结构组织，保证四跳可追溯：

## 原始需求
[一句话还原诉求]

## 设计目标
面向 [用户]，在 [场景] 下，通过 [干预]，实现 [可衡量结果]。

## 设计策略
1. 架构策略：……
2. 交互策略：……
3. 视觉策略：……

## 设计方案
- 页面：……
- 组件：……
- 异常/空/循环态：……
- 关键规则与默认值：……

参考示例（商家后台配置活动太复杂）：

  • 需求：商家反馈后台配置活动太复杂，很多不会用。
  • 目标：面向中小商家，首次配置活动场景，简化流程，使首次配置成功率 ≥ 85%，平均配置时间 ≤ 3 分钟。
  • 策略：① 三步向导式结构（选模板→填参数→预览）② 智能默认值 + 实时校验 + 一键应用 ③ 突出主操作、弱化高级设置。
  • 方案：3 个步骤页 + 1 个预览页；模板卡片 / 参数滑块 / 实时预览区；参数非法即时提示、断网自动保存草稿；默认推荐「同类商家高转化模板」。

交付产出（生成 MD / PDF 文件）

四跳走完后，必须把结果落地成文件，而不仅停留在对话里。

1. 选择格式

  • 用户已指定 MD 或 PDF → 直接生成。
  • 未指定 → 默认生成 MD（轻量、可二次编辑、版本可控）；若用户需要正式交付/评审稿，再生成 PDF。
  • 同时要两种时，先生成 MD，再由 MD 转 PDF（保持内容一致）。

2. 文件内容与命名

  • 内容用上文「输出格式」的完整结构（原始需求 / 设计目标 / 设计策略 / 设计方案），并在末尾附上三段自检清单的勾选结果，证明四跳自洽。
  • 命名：设计方案-<主题>-<YYYYMMDD>.md（或 .pdf）。
  • 写入位置：当前项目根目录下的 output/（不存在则创建）；纯 home 环境下写到用户指定目录或 ~/Desktop/。

3. 生成 MD

用 Write 工具直接写文件，无需依赖。这是默认、最可靠的交付方式。

4. 生成 PDF

内容为中文，PDF 必须用支持 CJK 的方式生成，遵循 pdf skill（/Users/hz-mb-0020/.codex/skills/pdf/SKILL.md）的规范。推荐两条路径，按环境择一：

  • 路径 A（推荐，免外部字体）：用 reportlab 内置 CJK 字体直接渲染。
from reportlab.lib.pagesizes import A4
from reportlab.lib.styles import getSampleStyleSheet
from reportlab.pdfbase import pdfmetrics
from reportlab.pdfbase.cidfonts import UnicodeCIDFont
from reportlab.platypus import SimpleDocTemplate, Paragraph, Spacer

pdfmetrics.registerFont(UnicodeCIDFont("STSong-Light"))  # 内置中文字体
styles = getSampleStyleSheet()
for s in styles.byName.values():
    s.fontName = "STSong-Light"
# 用 SimpleDocTemplate 把各段落 Paragraph 顺序写入即可
  • 路径 B（已装 pandoc 时）：pandoc 设计方案.md -o 设计方案.pdf --pdf-engine=xelatex -V CJKmainfont="PingFang SC"（需 xelatex + 中文字体）。

依赖缺失时按 pdf skill 指引安装（uv pip install reportlab 等）；装不上就告知用户缺哪个依赖，并先交付 MD 兜底。

5. 生成后校验

  • PDF：渲染首页为 PNG 检查（pdftoppm -png file.pdf out），确认中文无乱码/方块、排版无截断。
  • 向用户给出文件路径，并用 ![](绝对路径) 内联预览（PDF 预览首页 PNG）。

常见误区与反模式

需求 → 目标

  • 把功能当目标；只有业务目标没有用户收益（用户被诱导，留存崩）；指标不可衡量。

目标 → 策略

  • 把「更简洁的视觉」当策略（它只是表现层手段之一）；策略相互打架却无优先级；忽略非功能约束。

策略 → 方案

  • 跳过任务层直接画 UI（后期大量返工）；只画正常态（异常/空/循环/权限态缺失）；方案无法验证目标。
