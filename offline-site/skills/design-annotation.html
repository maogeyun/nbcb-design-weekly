用于设计稿标注说明。完成标注后，输出可视化标注图片 + 文档。核心产物为「整体分栏图」：左侧放置原始设计稿，右侧完整呈现全部标注子项内容（1-13 节所有细节，非摘要）。另生成各章节专用可视化图。系统补全隐式标注。Use when 设计稿标注、设计交付、整体分栏标注图、左侧设计稿右侧完整规格、可视化标注、design handoff、给开发的一图全览规格说明书。

设计稿标注

把设计稿转化为「开发能实现、测试能验收、团队可复用」的完整说明书。

何时启用

  • 用户要求为设计稿写标注说明、设计规格或开发交付文档，并需要高质量可视化标注图片
  • 特别需要「整体分栏图」：左侧为原始设计稿，右侧完整展示所有标注子项内容（1~13 节全部细节，而非仅摘要或图例）
  • 分享设计稿图片（或 Figma/MasterGo 截图），希望生成「左侧设计稿 + 右侧完整规格」的整体图 + 各章节专用可视化图 + 配套文档
  • 设计评审、交付或交接前，需要让开发「打开一张图就能看到全部可实现、可验收的规则」

输入要求（必备）

  • 设计稿图片（PNG/JPG/截图，必填）：用于生成整体分栏图的左侧。建议提供高清、完整页面视图。
  • 页面/模块基本信息（名称、版本、端、画布尺寸等）。
  • 可选：Figma/MasterGo 链接（用于提取更多交互原型细节）。

如果未提供设计图片，先要求用户上传，否则无法生成「左侧设计稿 + 右侧完整标注」的整体可视化。

核心一句话

> 设计稿标注 = 可见设计 + 设计稿未绘出的行为与边界。

>

> 重点任务：基于设计稿上已画出的元素，系统补全所有「开发无法从截图猜出来」的内容，例如：

> - 点击按钮后发生什么？跳转到哪里？打开什么弹窗？

> - 表单校验规则、触发时机、错误文案？

> - 加载、空、错误、权限不足、极限数据时页面如何展示？

只有把这些「隐式规格」也标注清楚，交付的设计稿才真正能落地。

标注范围清单（必须系统性覆盖）

| 类型 | 需要标注什么 | 目的 |

|----------------|----------------------------------|------------------|

| 基础信息 | 页面、版本、端、画布、断点 | 明确设计适用范围 |

| 布局间距 | 栅格、边距、间距、对齐、固定/自适应 | 保证结构还原 |

| 尺寸结构 | 宽高、容器、组件尺寸、溢出规则 | 避免开发猜尺寸 |

| 字体排版 | 字号、字重、行高、字间距、颜色 | 保证阅读层级 |

| 视觉样式 | 色值、透明度、圆角、描边、阴影、渐变 | 保证视觉一致 |

| 组件状态 | 默认、Hover、Pressed、Focus、Disabled、Loading、Error、Empty 等 | 保证状态完整 |

| 交互行为 | 点击跳转、弹层、校验、反馈、键盘、滚动、吸顶、拖拽 | 保证流程可实现 |

| 响应式适配 | 断点、列数变化、折叠/隐藏、触控热区、安全区 | 保证多端可用 |

| 资源切图 | 图标格式、倍率、命名、压缩、Lottie | 保证资源交付 |

| 动效转场 | 触发条件、时长、曲线、方向、透明度/位移/缩放 | 保证动态体验 |

| 内容文案 | 标题、Label、Placeholder、错误提示、单位、格式、脱敏 | 保证信息准确 |

| 业务边界 | 必填、权限、异常数据、极端场景、不可逆确认 | 保证方案完整 |

重点强化：设计稿「未直接展示」的隐式标注（本次优化核心）

设计稿通常只画「默认成功态」的静态画面。真正让开发卡壳的，是以下这些看不见的内容。本技能要求你必须主动挖掘并标注：

必须补全的隐式内容清单（逐项检查）

| 隐式内容 | 典型问题（必须回答） | 常见遗漏点 |

|------------------------|--------------------------------------------------------------------------------------|--------------------------------|

| 点击按钮后发生什么 | 点击主按钮/次按钮/链接后，立即反馈 → 异步请求 → 成功/失败 → 跳转/弹窗/刷新？ | 只写了「点击跳转」，没写中间态 |

| 页面如何跳转 | 是当前页替换、打开新标签、新开抽屉、还是返回上一页？有无返回数据携带？ | 没说明打开方式和参数传递 |

| 弹窗何时出现 | 什么操作触发？弹窗类型（Modal / Drawer / Popover / Toast）？出现位置、遮罩层？ | 只画了弹窗画面，没说触发条件 |

| 表单校验规则 | 哪些字段必填？格式限制？触发时机（输入时/失焦/提交）？错误文案？如何恢复？ | 只画了错误态 UI，没写规则 |

| 加载状态如何展示 | 全局 loading / 局部 skeleton / 按钮 spinner？时长预期？可否取消？ | 完全没画 loading |

| 空状态如何展示 | 首次无数据 / 筛选后无结果？展示文案、插画、操作按钮？ | 没区分不同空状态 |

| 错误状态如何提示 | 网络错误 / 校验错误 / 业务错误？Toast / 行内提示 / 弹窗？重试机制？ | 只画了成功，没画失败分支 |

| 权限不足时如何处理 | 按钮置灰？隐藏？提示文案？跳转登录/申请权限？ | 没考虑只读/无权场景 |

| 极限数据情况下如何展示 | 超长文本、极大数字、极多列表项（1000+）、零值、负值、溢出？截断/滚动/省略规则？ | 只按正常数据量设计 |

做法建议：

  • 以设计稿中每个可点击元素、表单、列表、卡片为锚点，反向提问。
  • 能从 Figma 原型/交互面板提取的优先提取；提取不到的，用标准问题清单向设计/产品确认。
  • 无法确认的，写明「假设」或「待确认」，并给出推荐默认行为。

工作流（推荐步骤）

  1. 明确上下文 + 获取设计图片

记录元信息，并要求用户提供设计稿图片（用于叠加标注）。

  1. 先标注可见设计（12 类）

按传统 12 类把稿子里「画出来的」全部记录。

  1. 重点挖掘隐式行为与边界（本次核心）

遍历可操作元素，补全第 13 节所有隐式内容（点击链路、跳转、弹窗、校验、状态、极限数据等）。

  1. 输出结构化文本文档

使用下方模板完成完整 Markdown（含第 13 节）。

  1. 生成可视化标注图片（交付关键步骤，必做）

基于文本标注 + 原始设计稿图片，生成以下可视化产物：

- 整体分栏图（00-overview-annotated.png，最核心交付物）：

- 布局严格为左右分栏：

- 左侧：原始设计稿（高清、按比例放置，可带少量编号图钉或连线指向右侧）。

- 右侧：完整标注内容（必须包含 1~13 节所有子项的全部细节，非摘要、非“核心 8~12 条”）。使用紧凑、专业的信息面板布局：章节标题、结构化列表、小表格、关键数值与规则。

- 推荐宽图（例如 2800~3600px 宽），以便右侧能容纳全部内容且保持可读性。

- 左侧与右侧通过编号、颜色或连线建立对应关系。

- 章节专用图：为重要章节各生成 1~3 张清晰可视化图片（详见 reference.md「可视化图片生成指南」）。

- 使用 GenerateImage 工具（整体图必须传入 reference_image_paths 指向原设计稿）。

- 所有图片命名规范、风格统一、专业易读（主色强调、清晰层级、足够对比度）。

- 在主文档中添加「可视化交付物索引」，用相对路径引用所有生成的图片。

  1. 整理交付文件夹 + 总结

按标准结构输出文档 + visuals/ 文件夹，并给出使用说明。

整体分栏图（00-overview-annotated.png）硬性要求：

  • 必须采用清晰的左右分栏布局：

- 左侧（约 40-50% 宽度）：完整放置原始设计稿（可适度缩小或保持比例，带少量编号/连线指向右侧）。

- 右侧（约 50-60% 宽度）：完整呈现 1~13 节所有标注子项的全部内容（页面基础信息、布局数值、字体参数、视觉 token、组件状态全集、交互规则、表单完整校验矩阵、加载/空/错误/权限/极限数据场景等）。使用结构化紧凑排版（大章节标题 + 子列表 + 小表格 + 关键值高亮）。

  • 左侧设计稿与右侧内容必须通过编号、颜色或虚线建立明确对应。
  • 推荐生成高分辨率宽图（宽度建议 2800~3600px+，高度根据内容自适应），确保右侧所有文字清晰可读。
  • 使用 GenerateImage 时必须传入原始设计稿作为 reference_image_paths。
  • 右侧内容要完整，不能只放“核心 8~12 条”或摘要。

其他章节专用图硬性要求：

  • 每个主要章节至少产出 1 张专用图；布局、状态、交互、隐式行为章节建议 2~3 张。
  • 风格统一、专业易读。
